# ParkSpot — Society Visitor Parking Slot Tracker

**Stack:** Java · Spring Boot · Spring Data JPA · MySQL · HTML/CSS/JavaScript

## 1. Objective
Give gate security staff a simple digital system to record visitor vehicles, assign numbered parking slots, release slots when vehicles leave, and keep a daily visitor log.

## 2. Real-world problem
A society has limited visitor parking used on a first-come basis. Nobody records who entered, which vehicle, which flat, which slot, or when it entered/left. This causes confusion and parking disputes.

## 3. Features
- **Login** for gate security (session based, password stored as BCrypt hash)
- Log visitor vehicle entry (vehicle number, flat, slot, entry time – generated by the server)
- Mark exit (exit time recorded, slot becomes AVAILABLE again)
- View available / occupied slots (with vehicle, flat, entry time)
- Prevent assigning an occupied slot and prevent double parking of a vehicle
- Daily visitor log with date filter and totals
- Search parking history by vehicle number, flat number, date
- Full REST API + global error handling + validation

## 4. Architecture
```
Browser (HTML / CSS / JavaScript, fetch API)
        │  JSON over HTTP
        ▼
Controller layer   (controller/)   – receives HTTP requests, returns responses
        ▼
Service layer      (service/)      – ALL business rules
        ▼
Repository layer   (repository/)   – Spring Data JPA, database access only
        ▼
MySQL database "parkspot"
```
Other packages: `entity/` (JPA classes), `dto/` (request/response objects), `exception/` (custom exceptions + `@RestControllerAdvice`), `config/` (login interceptor, data initializer).

The frontend files live in `src/main/resources/static`, so Spring Boot serves the website **and** the API from `http://localhost:8080`. Because it is one origin, **no CORS problem** occurs.

**Login flow:** `POST /api/auth/login` checks the BCrypt password and stores the username in the `HttpSession`. `AuthInterceptor` blocks every `/api/**` call without a session (HTTP 401). Each page calls `/api/auth/me` first and redirects to `login.html` when it gets 401.

## 5. Database design
| Table | Important columns |
|---|---|
| `visitor_vehicle` | id, vehicle_number (unique), vehicle_type, visitor_name, mobile_number |
| `flat` | id, flat_number (unique), resident_name |
| `parking_slot` | id, slot_number (unique), status (AVAILABLE / OCCUPIED) |
| `parking_record` | id, **vehicle_id**, **flat_id**, **slot_id**, purpose, entry_time (NOT NULL), exit_time, status (ACTIVE / COMPLETED) |
| `staff_user` | id, username (unique), password_hash, full_name |

Relationships (only where logical):
- `ParkingRecord` **@ManyToOne** `VisitorVehicle`, `Flat`, `ParkingSlot`
- `VisitorVehicle` **@OneToMany(mappedBy)** `ParkingRecord` (a vehicle can visit many times)
- `@OneToOne` is **not** used: a slot is linked to a vehicle only through the *active* record, and that changes over time.

**Why ParkingRecord?** A permanent vehicle↔slot link would be wrong: a slot is used by many vehicles over time and a vehicle uses many slots over time. ParkingRecord stores one visit (entry + exit), so the history is never lost.

## 6. Setup and run
**Requirements:** JDK 17+, Maven 3.8+, MySQL 8 (running).

1. Start MySQL and create the database (`database/setup.sql`):
   ```sql
   CREATE DATABASE parkspot;
   ```
2. Set the `DB_PASSWORD` environment variable to your MySQL password. (Change `spring.datasource.username` in
        `src/main/resources/application.properties` too if you do not use `root`.)
3. Run:
   ```
   mvn spring-boot:run
   ```
   (or open the folder in IntelliJ / Eclipse / VS Code and run `ParkSpotApplication`).
4. Open **http://localhost:8080** and log in with **username `admin` / password `admin123`**.

On first start the application creates the tables, slots P01–P10, sample flats 101–105 and the admin user. On restart it checks first, so nothing is duplicated.

## 8. Business rules (all in `ParkingService`)
| Rule | Where | Result |
|---|---|---|
| 1. Slot cannot be reused before exit | `ensureSlotAvailable()` | 409 "Parking slot P01 is already occupied." |
| 2. Entry time before exit time | `validateTimes()`; `entry_time` is NOT NULL | 409 |
| 3. No duplicate active parking | `ensureVehicleNotParked()` | 409 "Vehicle TN38AB1234 is already parked." |
| 4. Exit only active parking | `recordExit()` | 409 "Parking record has already been completed." |
| 5. Invalid slot | `registerEntry()` | 404 "Parking slot P99 does not exist." |

Both checks run **before** anything is saved. The slot row is loaded with `PESSIMISTIC_WRITE` (SELECT … FOR UPDATE) so two guards cannot take the same slot at the same time. A `@Transactional` method rolls back everything if any rule fails.

## 9. REST API
All `/api/**` (except login/logout) need a logged-in session.

| Method | URL | Description | Success |
|---|---|---|---|
| POST | /api/auth/login | Login `{username,password}` | 200 |
| POST | /api/auth/logout | Logout | 200 |
| GET | /api/auth/me | Current user | 200 |
| POST | /api/vehicles | Create vehicle | 201 |
| GET | /api/vehicles | List vehicles | 200 |
| GET | /api/vehicles/{id} | One vehicle | 200 |
| PUT | /api/vehicles/{id} | Update vehicle | 200 |
| DELETE | /api/vehicles/{id} | Delete vehicle (only if it has no parking records) | 204 |
| POST | /api/flats | Create flat | 201 |
| GET | /api/flats | List flats | 200 |
| GET | /api/flats/{id} | One flat | 200 |
| GET | /api/slots | All slots | 200 |
| GET | /api/slots/available | Available slots | 200 |
| GET | /api/slots/occupied | Occupied slots (with vehicle) | 200 |
| GET | /api/slots/{id} | One slot | 200 |
| POST | /api/parking/entry | Vehicle entry | 201 |
| POST | /api/parking/exit/{id} | Exit (id = parking record id) | 200 |
| GET | /api/parking/active | Vehicles inside | 200 |
| GET | /api/parking/history?vehicleNumber=&flatNumber=&date= | Completed visits (filters optional) | 200 |
| GET | /api/parking/report/daily?date=YYYY-MM-DD | Daily visitor log | 200 |
| GET | /api/dashboard | Dashboard numbers | 200 |

**Entry request** (`POST /api/parking/entry`):
```json
{
  "vehicleNumber": "TN38AB1234",
  "flatNumber": "101",
  "slotNumber": "P01"
}
```
If the vehicle is not registered yet, also send `visitorName`, `mobileNumber`, `vehicleType` (and optional `purpose`) and the vehicle is registered automatically — this is what the Register page does:
```json
{
  "visitorName": "Rahul Kumar", "mobileNumber": "9876543210",
  "vehicleNumber": "TN38AB1234", "vehicleType": "Car",
  "flatNumber": "101", "slotNumber": "P01", "purpose": "Family visit"
}
```
**Error format:**
```json
{ "timestamp": "2026-09-28T10:30:00", "status": 409, "message": "Parking slot P01 is already occupied." }
```
Validation errors (400) add an `errors` object with one message per field.

| Status | Used for |
|---|---|
| 200 / 201 / 204 | OK / created / deleted |
| 400 | Validation error, invalid JSON, invalid date |
| 401 | Not logged in / wrong password |
| 404 | Slot, flat, vehicle or record not found |
| 409 | Business-rule violation or duplicate |
| 500 | Database or unexpected error (no stack trace shown) |

## 10. Postman testing
Import `postman/ParkSpot.postman_collection.json` (variable `baseUrl = http://localhost:8080`).

**Run "0. Login" first.** Postman stores the session cookie and sends it automatically with the next requests.

Positive tests (folder *1*): Test 1 Create Flat → 2 Create Vehicle → 3 Available Slots → 4 Parking Entry → 5 Occupied Slots → 6 Active Parking → 7 Exit `POST /api/parking/exit/1` → 8 Daily Report `GET /api/parking/report/daily?date=2026-09-28` (use today's date).

Example bodies:
```json
POST /api/flats     { "flatNumber": "106", "residentName": "Lakshmi Narayanan" }
POST /api/vehicles  { "vehicleNumber": "TN38AB1234", "vehicleType": "Car",
                      "visitorName": "Rahul Kumar", "mobileNumber": "9876543210" }
```

## 11. Negative test cases (folder *2*)
| Case | Steps | Expected |
|---|---|---|
| 1 | Vehicle A → P01, then Vehicle B → P01 | **409** "Parking slot P01 is already occupied." |
| 2 | Enter the same vehicle again while it is inside | **409** "Vehicle TN38AB1234 is already parked." |
| 3 | Exit the same record twice | **409** "Parking record has already been completed." |
| 4 | Slot `P99` | **404** "Parking slot P99 does not exist." |
| 5 | Empty vehicleNumber / flatNumber / slotNumber | **400** with a message per field |
| 6 | Any `/api` call without login | **401** "Please log in to continue." |

All of these also work from the website (Register page, Active page Exit button).

## 12. Demo workflow
1. Start MySQL → create `parkspot` → run the app → open `http://localhost:8080` → login.
2. Dashboard: 10 available slots.
3. Register: Rahul Kumar, TN38AB1234, Flat 101, P01 → success message, P01 OCCUPIED.
4. Active Parking → Rahul's vehicle is listed.
5. Register another vehicle to P01 (tick "Show all slots") → rejected with the red error.
6. Active Parking → **Exit** → exit time recorded, P01 AVAILABLE.
7. Daily Visitor Log → today's date → the completed visit with entry and exit times.

## 14. Troubleshooting
| Problem | Fix |
|---|---|
| `Access denied for user 'root'` | Wrong password in `application.properties` |
| `Communications link failure` | MySQL is not running / port is not 3306 |
| `Port 8080 already in use` | Change `server.port` in `application.properties` |
| `release version 17 not supported` | Install JDK 17 or newer |
| Cannot log in | Default user is created only once; user `admin`, password `admin123` |
